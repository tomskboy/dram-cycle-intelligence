# Публикация дашборда в Streamlit Community Cloud

Дашборд только читает таблицы `data/processed/`, которые лежат в репозитории. Сборщики цен (`src/collect_*.py`) и конвейер при открытии приложения не запускаются, секреты и ключи не нужны.

## Что уже настроено в репозитории

| Файл | Зачем |
|---|---|
| `dashboard/app.py` | Точка входа. |
| `dashboard/requirements.txt` | Хостинг ищет файл зависимостей сначала рядом с точкой входа, потом в корне. Этот файл подключает `../requirements-dashboard.txt`: streamlit 1.65.0, pandas 3.0.6, altair 6.3.0 — версии, на которых проходят тесты. Корневой `requirements.txt` (Playwright для сборщиков) на хостинге не используется. |
| `.streamlit/config.toml` | Тема, меню только для просмотра, без сбора статистики использования. |
| `data/processed/*.csv` | Данные приложения. Если какой-то таблицы нет, приложение показывает понятную ошибку, а не трассировку. |

## Шаги публикации

1. Войдите на [share.streamlit.io](https://share.streamlit.io) через GitHub. Нужен аккаунт с правами администратора репозитория `tomskboy/dram-cycle-intelligence`.
2. При первом входе подключите GitHub: **Workspaces → Connect GitHub account → Authorize streamlit**. Для публичного репозитория доступ к приватным репозиториям не нужен.
3. Нажмите **Create app → Yup, I have an app**.
4. Заполните поля:
   - **Repository:** `tomskboy/dram-cycle-intelligence`;
   - **Branch:** `main`;
   - **Main file path:** `dashboard/app.py`;
   - **App URL** (необязательно) — например, `memory-cycle-2026`.
5. Откройте **Advanced settings** и выберите **Python version 3.11**. По умолчанию хостинг ставит 3.12. Версию Python после публикации поменять нельзя — только удалить приложение и опубликовать заново. Поле **Secrets** оставьте пустым.
6. Нажмите **Save** (или **Deploy**) и дождитесь сборки, обычно несколько минут.

## Проверка после публикации

- Открыты четыре раздела: «Стоимость сборок», «Структура расходов», «История цен», «Россия/США».
- Рядом с ценами видна дата снимка и валюта.
- В разделе «Россия/США» видны курс ЦБ на дату снимка и раскрытый блок «Ограничения сравнения».

## Обновление данных

Хостинг пересобирает приложение при каждом push в `main`. Новые цены попадают в дашборд так:
1. Собрать снимок локально (`python src/collect_regard.py`, `python src/collect_newegg.py`).
2. Добавить курс ЦБ на дату снимка в `data/reference/fx_rates.csv`.
3. Пересобрать таблицы: `python -m src.pipeline`.
4. Закоммитить и слить через PR — GitHub Actions проверит тесты и `--check`.

## Как это проверено без хостинга

В чистом окружении на Python 3.11, из корня репозитория:

```
python -m venv .venv && .venv/bin/pip install -r dashboard/requirements.txt
.venv/bin/streamlit run dashboard/app.py
```

Зависимости ставятся и через pip, и через uv: хостинг сначала пробует uv. В браузере открываются все четыре раздела, ошибок и исключений нет. Тест `HostedApp` в `tests/test_dashboard.py` проверяет то же автоматически:
- дату и валюту рядом с ценами;
- курс и ограничения сравнения;
- понятную ошибку без `data/processed`;
- запуск в отдельном процессе с отключённой сетью: модули сборщиков и конвейера не загружаются.
